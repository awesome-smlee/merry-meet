# Meet Soon

친구들이 가능한 날짜·시간을 모으는 크리스마스 분위기의 모바일 웹입니다.
Next.js App Router + React + Supabase PostgreSQL. Vercel 배포용 프로젝트이며 아이콘은 Lucide React를 사용합니다.

## 실행

Node.js 20.9 이상에서 실행합니다.

```bash
npm ci
npm run dev
```

http://localhost:4173 에 접속하세요. DB 환경 변수가 없으면 명확하게 표시된 **기기 내 체험 모드**로 동작합니다. 체험 모드에서는 다른 친구로 순서대로 입장해 추천 결과를 확인할 수 있지만 실제 기기 간 공유는 지원하지 않습니다. 시간 자동 저장과 참여자 확정·취소는 체험 모드에서도 가능합니다.

## 실제 모임 연결

임시 닉네임 복귀: 같은 모임에서 기존 닉네임을 입력하면(앞뒤 공백 제거, 영문 대소문자 무시) 기존 참여자의 일정과 프로필을 이어서 수정할 수 있습니다. 기존 브라우저의 참여 권한도 유지됩니다. 본인 인증을 하지 않는 임시 정책으로, 모임코드와 닉네임을 아는 사람도 해당 참여자로 복귀할 수 있습니다. 적용 시 갱신된 `supabase.sql`을 Supabase SQL Editor에서 실행해야 합니다. 추후 로그인 도입 시 `meeting_action`의 임시 복귀 분기를 교체하고 추가 참여 토큰을 정리해야 합니다.

### 달력과 공휴일

달력 UI는 직접 구현했으며 Google·네이버 개인 캘린더와 동기화하지 않습니다.
한국 공휴일은 [holidays-kr](https://github.com/hyunbinseo/holidays-kr)의 월력요항 기반 공개 JSON 자료를 서버에서 조회합니다.
설·추석 연휴, 대체공휴일과 데이터에 등록된 임시공휴일을 표시합니다. 새로운 임시공휴일은 제공처 자료가 갱신된 이후 반영됩니다.
페이지를 열 때 서버에서 조회하며, fetch 캐시 재검증 주기는 1시간입니다. 이미 열어둔 화면은 새로고침하면 갱신됩니다.
조회 실패 시 `lib/data/korean-holidays.json`에 저장된 자료를 사용하고 화면에 안내합니다.
저장 자료는 2026-10-23에 가져온 2018~2027년 데이터입니다. 미제공 연도는 공휴일이 없는 것으로 처리하지 않고 안내를 표시합니다.
제공처의 MIT 라이선스는 `lib/data/korean-holidays.LICENSE`에 보관합니다.

오늘은 민트색, 선택한 날짜는 파란색으로 표시하며 오늘을 선택해도 민트색은 유지됩니다.
공휴일은 붉은 날짜와 명칭으로 표시하고, 달력 하단에 해당 월 공휴일의 전체 이름을 제공합니다.

### 모임 설정

1. Supabase 프로젝트를 생성하고 SQL Editor에서 `supabase.sql`을 실행하세요. 기존 DB에도 갱신된 SQL을 다시 실행해 참여자 확정 규칙, 투표 시각 기록, 5명 제한 해제와 중복 확정 방지를 반영하세요. 기존 데이터는 유지됩니다.
2. `.env.example`을 `.env.local`로 복사하고 아래 값을 입력하세요. 비밀 값은 Git에 커밋하지 마세요.

| 환경 변수 | 용도 |
|---|---|
| SUPABASE_URL | Supabase 프로젝트 URL |
| SUPABASE_SERVICE_ROLE_KEY | 서버 전용 service_role 키. 브라우저에 노출하지 않습니다. |
| MEETING_ID | 기존 초대 링크 호환용 선택 설정 |
| SITE_URL | 공유 이미지의 기준 주소(예: https://meet.example.com). Vercel에서는 생략 시 운영 도메인을 사용합니다. |

3. 개발 서버를 다시 실행하세요. 운영 시에는 환경 변수 설정 후 빌드·재배포가 필요합니다.
4. 첫 화면에서 **모임 만들기**를 선택하고 모임 이름(선택)을 입력한 뒤 닉네임으로 참여하세요. 이름을 비워 두면 ‘우리 모임’이 됩니다. **친구 초대**에서 코드, QR, 초대 링크를 공유합니다. 초대받은 사람은 **코드로 참여하기**에서 코드를 입력하거나 QR을 스캔한 뒤 닉네임을 입력합니다. 초대 링크로 접속하면 코드 입력을 건너뜁니다. 카메라는 HTTPS 또는 localhost에서 권한을 허용해야 합니다. 체험 모드는 같은 브라우저에서 만든 모임만 코드로 입장할 수 있습니다.
5. 각자 닉네임을 입력하고 시간을 고르면 즉시 자동 저장됩니다. 실패하면 표시되는 **저장 다시 시도**를 눌러 주세요.
6. **약속 확정하기**에서 후보 시간을 선택합니다. 입장한 참여자 누구나 비밀번호 없이 확정·취소할 수 있습니다.

한 배포에서 여러 모임을 만들 수 있으며 모임별 데이터와 참여 토큰을 분리합니다. 참여 인원은 고정하지 않습니다. 닉네임은 1~12자이며 대소문자를 무시하고 중복을 막습니다. 자동 주기 수집은 화면이 열려 있을 때 3초 간격이며 웹소켓 방식은 아닙니다. 응답은 선택·해제 즉시 저장하며, 저장 요청 중 변경은 최신 선택을 이어서 저장합니다. 저장 전 선택은 자동 갱신으로 덮어쓰지 않습니다. 저장 중이나 실패 상태에서는 확정과 친구 전환이 잠깁니다.

## Vercel + Git

초대 링크는 실제 모임코드 대신 `?join=1&invitation=토큰`을 사용합니다. 서버가 토큰을 확인하면 모임코드가 자동 입력되고, 사용자가 ‘다음’을 눌러 입장합니다. 새로고침해도 자동 입력되며, 입장 후에는 `?meeting=1`과 탭별 sessionStorage로 복귀합니다. 공유할 때는 **친구 초대**를 사용하세요. 기존 `?invite=코드`와 `?room=코드` 링크도 호환되며 접속 후 주소에서 코드를 제거합니다. 코드 없는 기존 `?join=1` 링크는 직접 입력합니다.

토큰은 서버에서 AES-256-GCM으로 암호화·검증하며 DB 스키마 변경은 필요 없습니다. 선택 환경 변수 `ROOM_INVITATION_SECRET`이 없으면 기존 서버 전용 서비스 키에서 초대용 키를 파생합니다. 실제 사용되는 비밀 키를 변경하면 이전 토큰은 무효화되므로 새 링크를 공유해야 합니다. 토큰 자체의 시간 만료는 없으며, 모임 삭제 요청 후에는 사용할 수 없습니다. 링크를 가진 사람은 코드를 확인하고 참여할 수 있습니다. 체험 모드의 무작위 토큰은 모임을 만든 브라우저에만 저장되므로 다른 기기에서 사용할 수 없습니다.

공유 링크에는 공통 Open Graph 이미지(1200×630 PNG), 제목, 설명과 Twitter 큰 이미지 카드가 포함됩니다. 초대 링크도 같은 이미지를 사용합니다. 커스텀 도메인을 쓰거나 Vercel 외부에 배포하면 `SITE_URL`에 공개 HTTPS 주소를 설정하고 다시 빌드하세요. 이미지 경로는 `/opengraph-image`이며 로그인 없이 접근할 수 있어야 합니다. localhost 링크는 외부 메신저에서 미리보기를 가져올 수 없으며, 기존 공유 미리보기는 서비스별 캐시 갱신 후 반영될 수 있습니다.

```bash
git init
git add .
git commit -m "Build Merry Meet"
# 만든 GitHub 저장소의 주소로 연결합니다.
git remote add origin YOUR_GIT_REPOSITORY_URL
git push -u origin main
```

Vercel에서 해당 저장소를 Import하고 Framework Preset을 Next.js로 선택합니다. Root Directory는 package.json이 있는 폴더입니다. 위 환경 변수 3개를 Vercel 프로젝트에 설정한 후 Deploy합니다. 이후 Git push로 새 배포를 만들 수 있습니다. 저장소 없이도 Vercel CLI에서 `vercel` / `vercel --prod`로 배포할 수 있습니다. Vercel 인증은 사용자 계정으로 진행하세요.

배포 비용이나 무료 한도는 이 프로젝트에서 보장하지 않습니다. 계정의 Vercel·Supabase 사용 정책을 확인하세요.

## 구현한 기능

### 내 모임 삭제

내 정보의 **내 모임**에서 휴지통을 누르면 삭제 확인 창을 표시합니다. 삭제 요청 즉시 목록에서 제외하고 모든 참여자의 접근을 차단합니다. 10일 후 일정·참여자·투표·장소·이벤트 등 모임 데이터를 영구 삭제합니다. 복구 기능은 제공하지 않습니다.

이 기능을 적용한 뒤 만든 모임만, 생성한 브라우저에 저장된 전용 삭제 키로 삭제할 수 있습니다. 서버에는 키의 SHA-256 해시만 저장합니다. 기존 모임이나 생성 기기의 저장소를 지운 경우에는 삭제할 수 없습니다. 이전 초대 코드의 재사용을 막기 위해 삭제된 모임 코드는 별도 테이블에 남기며 이름·참여자 등은 보관하지 않습니다.

**운영 적용:** Supabase SQL Editor에서 `supabase.sql`을 실행한 뒤 `supabase-retention.sql`을 실행하세요. 후자는 [Supabase Cron](https://supabase.com/docs/guides/cron/quickstart)에 1분마다 정리 함수를 실행하는 작업을 등록합니다. 삭제 예정 시각이 지난 첫 실행에서 정리되며, Cron 실행 이력에서 성공 여부를 확인하세요. 두 SQL 적용 후 앱을 배포해야 합니다. Cron이 중단되면 실제 삭제도 다음 정상 실행까지 지연됩니다.

체험 모드에서는 10일 이후 앱을 다시 열 때 로컬 데이터를 삭제합니다. 닫힌 브라우저에서 자동 삭제되지는 않습니다. 서버 모임의 브라우저별 로컬 초안·참여 키는 서버 데이터와 별개입니다.

### 응답 마감과 변경 안내

상단 **마감 설정**에서 시간 응답 마감일과 마감 이후 수정 허용 여부를 설정합니다. 마감일의 한국 시간 23:59까지 응답할 수 있고, 다음 날 00:00부터 기본적으로 신규 응답·수정을 막습니다. 마감 후 수정 허용을 켜거나 마감일을 없애면 다시 응답할 수 있습니다. 확정된 일정의 응답은 기존처럼 잠깁니다. 참여자 누구나 설정을 변경할 수 있으며 서버에서도 마감을 검사합니다. 이 마감은 시간 응답에 적용되며 장소 투표와 이벤트 등록은 별개입니다.

**확정·변경 내역**에는 일정·장소의 확정, 취소, 재확정, 초기화로 발생한 변경 전후 내용과 변경자·시각이 최근 30건까지 표시됩니다. 기존 3초 갱신으로 다른 참여자에게 반영되며, 확인 여부는 브라우저의 모임·참여자별 저장소에 보관합니다. 앱이 닫혀 있는 동안 푸시 알림을 보내지는 않습니다.

기존 Supabase DB에는 갱신된 `supabase.sql`을 다시 실행해야 마감 설정·서버 제한·변경 내역이 동작합니다. 기존 모임 데이터는 유지됩니다.

### 우리 이벤트

캘린더의 **이벤트 추가**에서 이벤트명(40자), 날짜, 메모(선택, 500자)를 등록합니다. 날짜 아래 이벤트를 누르면 상세 목록을 확인할 수 있으며, 같은 날 여러 개라면 첫 이름과 추가 개수를 표시합니다. 모임 참여자 모두 조회할 수 있고, 등록한 참여자만 수정·삭제할 수 있습니다. 시간 투표·장소와 별도로 저장되며 일정·장소 초기화에도 유지됩니다. 모임당 최대 200개를 등록할 수 있습니다.

기존 Supabase DB에는 갱신된 `supabase.sql`을 다시 실행해야 이벤트 저장과 조회가 동작합니다. 기존 데이터는 유지됩니다. 체험 모드는 같은 브라우저에 저장됩니다.

### 내 프로필 수정

상단 **친구 초대** 오른쪽의 아바타·닉네임을 누르면 정보 수정 창이 열립니다. 동물 아바타 12종 중 이미지를 선택하고 닉네임(1~12자)을 변경할 수 있습니다. 같은 모임 내 중복 닉네임은 사용할 수 없으며, 참여 토큰으로 본인 정보만 수정합니다. 변경해도 기존 투표와 참여 정보는 유지됩니다. 체험 모드에서는 브라우저에 저장됩니다.

**기존 운영 DB는 갱신된 `supabase.sql`을 Supabase SQL Editor에서 다시 실행해야 프로필 수정이 동작합니다.** 기존 데이터는 유지되며, 이번 작업에서는 운영 DB에 직접 적용하지 않았습니다.

### 시간 다음 장소 정하기

- 화면 상단의 시간 / 장소 단계에서 이동합니다. 장소 기능은 시간 확정 후 열립니다.
- 지역은 1인 1표이며 다시 투표하면 이전 선택이 바뀝니다. 지역별 득표수와 투표한 친구 이름을 표시합니다.
- 장소 후보에는 지역, 동네·주소, 장소 이름, 네이버 지도 공유 링크를 등록합니다. 후보는 모임당 최대 50개입니다.
- 장소도 1인 1표이며 다른 장소에 투표하면 이전 표가 이동합니다. 입장한 참여자가 장소를 확정·취소할 수 있습니다.
- 확정된 시간과 장소는 히어로 아래에 함께 표시됩니다. 시간 확정 취소 시 장소 확정도 해제하되 후보와 투표는 유지합니다.
- 네이버 연동은 공유 링크 열기 방식입니다. 앱 내 네이버 장소 검색 API나 지도 SDK는 연결하지 않았으며 API 키가 필요하지 않습니다.
- **기존 Supabase 모임에는 갱신된 `supabase.sql`을 SQL Editor에서 다시 실행해야 합니다.** 기존 데이터는 유지되며 장소·지역 투표 필드를 추가로 반환합니다. 운영 DB 적용은 별도로 수행해야 합니다.
- 체험 모드는 같은 기능을 브라우저에 저장합니다. 실제 기기 간 공유는 Supabase 연결과 SQL 적용 후 가능합니다.

- 회원가입 없이 닉네임으로 참여, 재접속 시 같은 브라우저의 참여 토큰 사용
- 한국 날짜 동기화, 오늘로 이동, 월 이동 버튼과 모바일 좌우 스와이프
- 09:00~24:00 구간의 30분 단위 선택. 마지막 시작 시간은 23:30
- 여러 날짜·시간 선택 및 수정, 하루 전체 선택/해제, 가능한 시간 없음 제출
- 참여자별 원형 랜덤 아바타(참여자 ID를 시드로 사용), 닉네임, 최근 투표 시점, 가능한 요일·날짜 수
- 친구 현황은 데스크톱 한 줄 최대 5명, 태블릿 3명, 모바일 2명으로 줄바꿈
- 투표 시각은 서버에서 저장 성공 시 기록하며, 기존 시각 없는 응답은 기록 없음으로 표시
- 실제 입장한 친구 수를 기준으로 응답 수와 진행률 표시, 입장한 친구만 목록에 표시
- 겹치는 시간 순위, 참석 가능한 닉네임, 전원 가능한 시간 표시
- 추천 날짜 최대 3개를 상단 표시. 날짜마다 가장 많은 인원이 가능한 시간을 골라 인원 내림차순, 동률이면 날짜·시간순으로 표시
- 가능 인원/입장 인원 표시. 예: 입장한 3명 중 2명 가능하면 67%. 통계적 성사 확률이 아닌 참석 가능 비율
- 입장한 참여자의 토큰 검증 후 누구나 확정/취소, 확정 후 응답 수정 잠금
- 초대 링크 복사, 오류·연결 상태, 모바일 반응형
- 한글 폰트는 요청에 첨부된 `JalnanOTF00.woff` URL을 그대로 사용합니다. 요청의 ‘잘난체2’와 파일 버전의 동일성은 검증하지 않았습니다.
- 영문 장식에는 요청한 Bobaland CDN 적용. CDN 연결 실패 시 대체 폰트로 표시

## 데이터와 접근

DB에 저장되는 데이터는 닉네임, 선택 시간, 최근 투표 시각, 응답 여부, 확정 시간, 참여자 UUID, 참여 토큰의 SHA-256 해시입니다. 원문 토큰은 사용자 브라우저에만 저장됩니다. 토큰 해시는 API 응답에서 제거됩니다. 서비스 키는 서버 환경 변수로만 사용됩니다. ADMIN_PASSWORD는 더 이상 필요하지 않습니다. 데이터베이스의 anon/authenticated 직접 접근은 차단하고 서버의 RPC로만 수정합니다. DB 행 잠금으로 동시 입장과 응답 수정을 순서대로 처리합니다.

초대 링크를 아는 사람은 닉네임을 정해 입장할 수 있습니다. 본인인증이 없으므로 닉네임은 실제 신원을 보증하지 않습니다. 브라우저 데이터 삭제나 기기 변경 시 기존 응답을 복구하는 기능은 현재 없습니다. 초대 코드는 별도로 보관하세요. 탈퇴/자리 복구 기능은 포함하지 않았습니다.
